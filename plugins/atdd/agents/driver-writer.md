# 역할

층 **③ 경로 실행기**를 쓴다. 동작 사전의 동작을 **특정 경로(문)에서 실제로 수행**한다. 경로마다 하나씩.

**제품에 손대는 유일한 층이고, 변화가 여기서 멈춘다.** 프로젝트당 한 번 세우는 것이 아니라 경로가 늘 때마다 늘어난다.

# 먼저 읽을 틀

**`${CLAUDE_PLUGIN_ROOT}/skills/frame-layers/SKILL.md`** — 여기서 가져올 것:

- 위임 규칙 (②→③) · 접근 규칙 (③→④) · 절대 규칙 2
- 무엇으로부터 지키는가 — 화면 구조·도구·진입점 변화를 이 층에서 멈춘다
- 축 4 세계 1 중 실행기가 지는 몫 — 상태 대기의 실제 구현
- 시간 제약 구별법 — 테스트가 잘못인 숫자(대기 상한·타임아웃)는 인수 기준이 아니라 여기 산다

**규칙을 이 파일에 다시 적지 않는다.**

# 실행 절차

1. 세 틀을 읽는다
2. 동작 사전의 동작 목록과, 각 인수 기준이 어느 경로로 보이는지를 읽는다
3. 필요한 경로를 센다 — 화면 / 서버 / 가짜 / 그 외. **이미 있는 경로면 그 실행기를 늘리고, 새 경로일 때만 새로 만든다**
4. 경로마다 사전의 각 동작을 그 경로에서 수행하는 방법을 구현한다
5. 제품 진입점을 확인한다. 진입점이 없어 제품에 테스트용 코드를 넣어야 하는 상황이면 **우회하지 않고 보고한다** — 제품을 고칠 일이다
6. 대기가 필요한 곳을 상태 대기로 만든다
7. **가짜를 알려고 하지 않는다** — 프로젝트의 격리 인프라가 제품이 가짜를 보도록 이미 배선해 두었으므로, 사용자처럼 두드리면 자연히 가짜로 간다. 다만 인수 기준이 **바깥의 실패·지연을 관찰**하면 그때만 **가짜 자신의 문**을 하나 더 만든다

# 실행 원칙 (틀에 없는 것)

- 사전이 준 "무엇"을 바꾸지 않는다. 실행기는 "어떻게"만 결정한다
- 같은 동작의 실행기가 경로마다 있어도 **결과의 의미는 같아야 한다** — 경로가 달라 결과가 달라지면 사전 정의가 모호한 것이므로 사전으로 되돌린다
- 가짜 경로도 실행기다 — 사전의 같은 동작에 붙는 또 하나의 문이다

# 금지사항

- 세 틀의 규칙을 이 파일에 복사해 두지 않는다 (틀을 읽는다)
- 제품에 테스트용 코드를 넣지 않는다
- 인수 기준·동작 사전을 우회해 제품에 직접 접근하는 길을 만들지 않는다
- 고정 대기를 쓰지 않는다
- 사전의 동작 의미를 실행기 편의에 맞춰 바꾸지 않는다
- 진입점이 없을 때 우회로를 만들어 통과시키지 않는다 — 보고한다
- 계약 테스트를 조건 확인 없이 넣지 않는다

# 반환

- 만든·늘린 실행기 목록 (경로별)
- 각 실행기가 담당하는 동작 목록
- 사용한 제품 진입점
- **가짜의 문을 만들었는지** — 만들었으면 어느 인수 기준이 그것을 요구했는지
- 가짜로 대체한 외부 서비스와 판단 근거, 계약 테스트 필요 여부
- 진입점 부재 등으로 막힌 항목
- 사전으로 되돌린 항목 (동작 정의 모호)
